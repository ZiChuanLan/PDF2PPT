# 管理页面重构：用户管理 + 重置密码

## Goal

将密码管理功能从设置页面分离，建立独立的管理页面体系：
- 普通用户：`/manage` 页面，显示账号信息 + 修改自己的密码
- 管理员：`/admin` 页面，保留现有功能 + 添加重置任意用户密码功能
- 设置页面：去掉"修改密码"，只保留业务配置

## Requirements

### 普通用户管理页面 (`/manage`)
- [ ] 显示当前用户账号信息（用户名、角色、配额、创建时间等）
- [ ] 修改自己的密码（旧密码 + 新密码 + 确认密码）
- [ ] 所有已登录用户可访问

### 管理员管理页面 (`/admin`)
- [ ] 保留现有用户管理功能（列表、批量删除、添加用户）
- [ ] 添加"重置密码"功能：管理员可重置任意用户的密码（无需旧密码）
- [ ] 用户列表中每行添加"重置密码"操作按钮

### 设置页面 (`/settings`)
- [ ] 移除"修改密码"卡片

### 导航更新
- [ ] 导航栏"管理"链接：管理员 → `/admin`，普通用户 → `/manage`

## Technical Approach

### 后端
- 复用现有 `POST /api/v1/auth/change-password` 端点（用户修改自己的密码）
- 新增 `POST /api/v1/admin/users/{user_id}/reset-password` 端点（管理员重置密码）
- 新增 `ResetPasswordRequest` Pydantic 模型（new_password）

### 前端
- 新增 `web/src/app/manage/page.tsx` — 普通用户管理页面
- 修改 `web/src/app/admin/page.tsx` — 添加重置密码功能
- 修改 `web/src/app/settings/page.tsx` — 移除修改密码卡片
- 修改导航组件 — 根据用户角色显示不同链接

## Acceptance Criteria

- [ ] 普通用户访问 `/manage` → 显示账号信息 + 修改密码
- [ ] 管理员访问 `/admin` → 用户列表有"重置密码"按钮
- [ ] 管理员重置密码 → 用户下次登录用新密码
- [ ] 设置页面不再显示"修改密码"
- [ ] 导航栏"管理"链接根据角色指向正确页面

## Out of Scope

- 密码重置邮件通知
- 密码强度要求配置
- 用户自助找回密码功能
