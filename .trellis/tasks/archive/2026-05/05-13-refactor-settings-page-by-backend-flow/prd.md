# 重构设置页面：基于后端处理流程

## Goal

重新设计前端设置页面，使其清晰映射后端处理流程（解析→识别→输出），消除当前4标签页设计中的混淆点（如"PPT提供方"等术语），让不熟悉项目的用户也能直观理解配置选项的含义。

## What I already know

* 当前设计问题：
  - 4标签页结构（基础设置、OCR设置、AI设置、高级设置）不符合用户心智模型
  - "PPT提供方"等术语令人困惑
  - 高级设置将所有提供方配置混在一起
  - 不熟悉项目的用户难以理解配置逻辑

* 后端处理流程（已研究）：
  - 阶段1：文档解析（Parse Engine Mode: local_ocr, remote_ocr, baidu_doc, mineru_cloud）
  - 阶段2：文字识别（OCR Provider: machine, tesseract, paddleocr, aiocr, baidu, auto）
  - 阶段3：布局辅助（Layout Assist）
  - 阶段4：PPT生成
  - 配置项之间存在依赖关系（如remote_ocr模式下有ai_ocr_chain_mode选项）

* 技术约束：
  - 前端框架：React + TypeScript
  - 状态管理：需要处理配置依赖和动态显示逻辑
  - 需要保持与现有API接口兼容

## Decision (ADR-lite)

**Context**: 用户反馈当前4标签页设计混乱，要求按照后端逻辑重构。研究显示后端有清晰的处理阶段（解析→识别→输出）。

**Decision**: 采用**方案A：流程导向设计**
- 按处理阶段组织设置（文档解析方式 → 文字识别策略 → 输出质量）
- 使用渐进式显示（根据解析方式动态显示相关识别选项）
- 使用面向用户的术语（描述功能而非技术名称）

**Consequences**: 
- 优点：直接映射后端逻辑，减少认知负担，配置依赖关系清晰
- 缺点：需要实现动态显示逻辑，可能需要用户理解处理流程
- 风险：需要确保所有现有配置项都能在新结构中找到位置

## Requirements

* 按处理流程组织设置页面：
  - 第一部分：文档解析方式（4种模式选择）
  - 第二部分：文字识别策略（根据解析方式动态显示）
  - 第三部分：输出质量控制

* 场景预设作为可选快速入口：
  - 页面顶部提供"快速配置"区域（普通文档/扫描件/高精度等预设）
  - 预设卡片点击后自动填充对应的流程配置
  - 下方始终显示完整的流程配置选项，用户可以在预设基础上微调
  - 预设区域可折叠，不强制使用

* 高级选项组织方式：
  - 采用混合策略：
    - 与流程相关的高级选项分散到对应部分（如"AIOCR并发设置"放在云端解析下方）
    - 通用高级选项（如图片处理参数、提示词覆盖）放在独立的折叠区域
  - 所有高级选项默认折叠，避免干扰主流程
  - 使用CollapsibleSection组件保持一致的交互模式

* 渐进式显示逻辑：
  - 选择"本地解析"时显示：机器提取/Tesseract/PaddleOCR/智能选择
  - 选择"云端解析"时显示：直接识别/文档解析模式/布局分块模式
  - 其他模式显示对应的识别选项

* 配置验证策略：
  - 实时禁用/隐藏不兼容选项（防止用户选择无效组合）
  - 根据解析方式动态显示相关的高级选项（如AIOCR并发设置仅在remote_ocr时显示）
  - 使用disabled状态和条件渲染实现

* 使用清晰的用户导向术语：
  - 避免"PPT提供方"等技术术语
  - 使用"文档解析方式"而非"parse_engine_mode"
  - 使用"文字识别策略"而非"ocr_provider"

* 默认值和初始状态：
  - 显示推荐配置作为默认值（本地解析 + 智能选择OCR）
  - 如果用户已有保存的配置，则显示用户配置
  - 推荐配置应该适合大多数场景，降低新用户的配置门槛

## Technical Approach

### 页面结构设计

```
┌─────────────────────────────────────────┐
│ 快速配置（可折叠）                        │
│ [📄 普通文档] [📸 扫描件] [🌐 高精度]    │
└─────────────────────────────────────────┘

┌─ 1. 文档解析方式 ──────────────────────┐
│ ○ 本地解析（快速，支持扫描件）           │
│ ○ 云端解析（高精度，需要API）            │
│ ○ 百度文档解析（专用接口）               │
│ ○ MinerU云端（结构化文档）              │
│                                          │
│ ▼ 高级选项（根据选择动态显示）           │
└─────────────────────────────────────────┘

┌─ 2. 文字识别策略 ──────────────────────┐
│ （根据解析方式动态显示相关选项）         │
└─────────────────────────────────────────┘

┌─ 3. 输出质量 ──────────────────────────┐
│ □ 启用布局辅助                           │
│ □ 智能文本优化                           │
│ ▼ 高级选项（折叠）                       │
└─────────────────────────────────────────┘

┌─ 通用高级设置（折叠）──────────────────┐
└─────────────────────────────────────────┘
```

### 实现要点

1. **组件拆分**：
   - `QuickPresets.tsx` — 快速配置预设卡片
   - `ParsingSection.tsx` — 文档解析方式选择
   - `OcrSection.tsx` — 文字识别策略选择
   - `OutputSection.tsx` — 输出质量控制
   - `AdvancedSection.tsx` — 通用高级设置

2. **动态显示逻辑**：
   - 使用 `settings.parseEngineMode` 控制识别策略选项显示
   - 使用条件渲染 `{settings.parseEngineMode === 'remote_ocr' && ...}`
   - 高级选项根据主选项动态显示/隐藏

3. **配置依赖处理**：
   - 当 `parseEngineMode` 改变时，检查并重置不兼容的子选项
   - 使用 `useEffect` 监听关键配置变化
   - 提供合理的默认值回退

4. **术语映射**：
   - `parse_engine_mode` → "文档解析方式"
   - `local_ocr` → "本地解析"
   - `remote_ocr` → "云端解析"
   - `ocr_provider` → "文字识别策略"
   - `machine` → "机器提取"
   - `aiocr` → "AI识别"

5. **文件修改范围**：
   - 主要重构 `web/src/app/settings/page.tsx`
   - 拆分现有的 `basic-settings.tsx`, `ocr-settings.tsx`, `advanced-settings.tsx`
   - 保留 `settings-shared.tsx` 中的共享组件
   - 保持 `use-settings` hook 不变（仅UI重构）

## Acceptance Criteria

* [ ] 设置页面按处理流程分为3个清晰的部分
* [ ] 页面顶部有可折叠的"快速配置"预设区域
* [ ] 预设卡片点击后正确填充对应的流程配置
* [ ] 新用户首次打开显示推荐配置（本地解析 + 智能选择）
* [ ] 已有配置的用户显示其保存的配置
* [ ] 根据解析方式选择，动态显示相关的识别选项
* [ ] 不兼容的选项自动禁用或隐藏，防止无效配置
* [ ] 流程相关的高级选项分散到对应部分，默认折叠
* [ ] 通用高级选项集中在独立折叠区域
* [ ] 所有术语使用用户友好的描述性文字
* [ ] 不熟悉项目的用户能够理解每个选项的作用
* [ ] 所有现有配置项都能在新界面中访问
* [ ] 配置依赖关系正确处理（如remote_ocr → ai_ocr_chain_mode）
* [ ] 与现有API接口完全兼容
* [ ] 用户可以在预设基础上进行微调

## Definition of Done

* 前端代码实现完成（React组件 + 状态管理）
* 动态显示逻辑测试通过
* 配置保存/加载功能正常
* UI/UX符合设计要求
* 代码通过lint和typecheck
* 更新相关文档

## Out of Scope

* 后端API修改（保持现有接口不变）
* 配置项的新增或删除（仅重新组织现有配置）
* 移动端适配（如当前设计不支持则暂不支持）
* 配置导入/导出功能
* 配置历史记录或版本管理
* 多语言支持（当前仅中文）
